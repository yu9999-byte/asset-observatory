## 目标与当前状态

- 产品面向外部用户开放，首期按零预算验证可用范围。
- 核心流程为“行情首页 → 币种持仓地址 → 地址转账事件”，以 CoinAnk、Arkham 为比较参考，逐项核对资产身份、指标口径、时间和覆盖。
- 用户提到 CoinAnk 有 800 多个币种，这是待核实的对齐目标，尚不是独立验证过的数量；其他来源的目录不能直接视为同一市场范围。
- 当前尚没有同时满足免费、覆盖够用、稳定且明确允许对外展示的完整数据组合。
- 尚未注册账号、申请 API Key 或启用新数据源。下列途径均需按各行状态继续核实。
- 先验证数据获取，再确定采集和存储方案；需要持久化时采用 MySQL。MySQL 是存储工具，不是数据来源。

## 申请时需要确认的内容

申请服务时说明产品面向外部用户开放，并询问：

1. 是否提供免费 API 或试用，需要哪些注册资料，是否要求绑卡，试用结束是否自动收费。
2. 可用链、资产、接口字段、历史范围和更新时间，是否覆盖 JCT 对应的准确链与合约。
3. 免费额度按请求、credits 还是其他单位计费，各接口成本、限速和额度耗尽行为。
4. 是否允许外部产品展示、必要的缓存和数据库存储、衍生指标计算，以及具体署名要求；按所需用途核对适用条款，存在歧义时取得书面澄清。
5. Key 获取和管理方式，以及停用、删除和数据保留要求。

注册需要的邮箱、验证码或其他真实资料由用户提供或本人在官方页面填写；不猜填身份资料。用户已提出协助注册的请求，后续按具体页面推进，涉及付费或发布仍需另行确认。不得在文档、代码仓库或聊天记录中保存密码和 API Key。

## 获取后的完成标准

拿到账号或 Key 仅代表获得了验证入口，不代表数据接入完成。每个来源都需留下实际响应、采集时间、来源时间、配额、使用条件、覆盖与缺失记录，再验证 Java 后端连通性、精度、分页、去重和异常处理。与参考网站对账时保留同一资产、时间、单位、市场范围及差异原因；缺失不按零处理，样本不冒充全量。
